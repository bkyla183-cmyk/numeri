How It Works & Mathematical Principles

A permutations calculator computes P(n, r)—the exact number of ordered arrangements of r items chosen from n distinct items when selection sequence matters.

Whenever order changes the outcome—such as race podium rankings (Gold/Silver/Bronze), PIN passcodes without repetition, or job scheduling—permutations multiply downward from n across r steps.

Governing Equation
P(n, r) = n! / (n - r)! (for integers 0 ≤ r ≤ n)

Step-by-Step Worked Calculation Example

Scenario: Awarding 1st, 2nd, and 3rd place medals (r = 3) among n = 8 sprinters.

  • Apply falling factorial: P(8, 3) = 8! / (8 - 3)! = 8! / 5!.
  • Cancel common factors: 8 × 7 × 6 = 336 distinct podium outcomes.

Result: 336 Permutations

Because 1st-2nd-3rd matters, the same three athletes can occupy 6 different podium orders.

Using Permutations When Group Order Is Irrelevant

Choosing a 3-person committee where roles are identical is a combination problem C(n, r), not a permutation P(n, r).

Frequently Asked Questions

What is the main difference between permutations (nPr) and combinations (nCr)?

Order matters in permutations (e.g., finishing 1st, 2nd, 3rd or setting a PIN code), whereas order does not matter in combinations (e.g., picking a committee of 3 people).

Why does 0! (zero factorial) equal 1 in nPr formulas?

There is exactly 1 way to arrange zero items, and defining 0! = 1 preserves the identity nPn = n! / (n − n)! = n! / 0! = n!.

Why do calculator factorials stop or lose exact integer precision above n = 170?

170! is approximately 7.26 × 10^306, whereas standard IEEE 754 64-bit floating-point numbers overflow above 1.797 × 10^308 at 171!.
